How it works

1. The handshake

The client and the server each make a 2048-bit RSA key pair. The client calls Products.Handshake with its public key, and the server replies with its own. Public keys are not secret, so this call is not sealed.

2. Sealed requests

For each command, the client writes the request as JSON and encrypts it with the public key of the server (RSA-OAEP). Only the private key of the server can open it. A long message is cut into blocks of 190 bytes.

3. Sealed replies

The server opens the request, runs it on the catalog, and seals the reply with the public key of the client. Errors, such as an unknown id, are inside the sealed reply too.

4. What the wire shows

net/rpc sends the method name, such as Products.Create, in plain text, and the sealed blocks encoded by encoding/gob. Open "bytes on the wire" under a command to see them.
